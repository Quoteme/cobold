Abstract

COBOLD is a side-scrolling platformer whose rules live entirely in the GnuCOBOL PROCEDURE DIVISION: a state record, a per-frame transition function, and a handful of external services (pixel collision, rendering, persistence) reached the same way a banking program reaches CICS or a data-access module — by CALL, never by inlining someone else's concerns. This page derives that transition function from first principles and shows, inline, the exact COBOL, C, and Nix source that implements each piece.

§1State

A session is a tuple

$$ \sigma = \langle \mathbf{p}, \mathbf{v}, f, g, \ell, c \rangle $$

of subpixel position (PLY-X, PLY-Y), subpixel velocity (PLY-VX, PLY-VY), facing PLY-FACING ∈ {0,1}, ground contact PLY-GROUNDED-FLAG, a ledger ℓ = (balance, overdrafts), and a run/won/quit status code c. Every field is declared PIC S9(9) COMP-5 — a signed 32-bit fullword — without exception; §6 explains why that uniformity is load-bearing, not decoration.

§2The frame transition

Let Δ be one call to 2000-GAME-LOOP. It factors as a composition of six independent paragraphs, each reading and writing only its own slice of σ:

$$ \Delta = \textsf{render} \circ \textsf{camera} \circ \textsf{collide} \circ \textsf{physics} \circ \textsf{input} $$

input maps the polled keyboard state to a desired velocity and a jump edge; physics integrates gravity and projects the subpixel position down to whole screen pixels (PLY-PX, PLY-PY, §3); collide depenetrates against the level mask and marks pickups (§4); camera re-centres the viewport and advances the sprite-animation clock; render is the only paragraph that ever calls out to SDLSHIM to draw.

§3Physics in subpixels

GnuCOBOL's COMP-5 is a machine integer: it has no representation for “half a pixel of fall per frame.” Rather than round every velocity to the nearest whole pixel — which reads, at low speeds, as visible stutter — position and velocity are integrated in a scaled integer domain, exactly the device a ledger uses to book money in cents rather than fractional currency:

$$ \text{pixel} = \left\lfloor \frac{\text{subpixel}}{s} \right\rfloor, \qquad s = 8 $$

Only the projected pair (PLY-PX, PLY-PY) is visible to collision, the camera, and rendering; gravity and velocity accumulate in the finer domain untouched. One frame of free fall is

$$ v_{t+1} = v_t + g, \qquad y_{t+1} = y_t + v_{t+1} $$

with g = 4 subpixels/frame² (0.5 px/frame²). A jump is a single impulse v_0 applied at take-off with no further thrust while the key is held (2100-READ-INPUT) — gravity alone then shapes the remaining trajectory into the textbook parabola

$$ y(t) = y_0 + v_0 t + \tfrac{1}{2} g t^2, \qquad h_{\max} = \frac{v_0^{\,2}}{2g} $$

With v0 = -80 subpixels (-10 px/frame) and g = 4 subpixels/frame², peak height works out to exactly 100 screen pixels.

§4Collision as a predicate

Level geometry is not a table of rectangles: it is a pixel image. assets/landschaft-k.png, pixel-aligned to the background (-h) and foreground (-v) art it was cut from, defines

$$ \textsf{solid} : \mathbb{Z} \times \mathbb{Z} \to \mathbb{B}, \qquad \textsf{solid}(x,y) = \bigl[\, \alpha(x,y) > 128 \,\bigr] $$

read once at start-of-day into a CPU-side surface (never rendered) and queried, one point at a time, across the CALL boundary by sdl_mask_solid. Depenetration is a search rather than a closed-form solve: on landing, JUMPRUN steps the feet upward one pixel at a time until the predicate clears,

$$ n^{*} = \min \{\, n \ge 0 : \neg\,\textsf{solid}(\text{feet}(x, y-n)) \,\}, \qquad y' = y - n^{*} $$

and the mirror image for ceilings and walls. The same WS-DID-CORRECT flag that drives the loop also decides whether the corresponding velocity component is zeroed.

§5Persistence as relations

Score is not a mutable cell; it is an audit trail. Every finished session is one row appended to a two-relation schema:

relationattributes
accountsid (pk), name
ledger_entries id (pk), account_id (fk), played_at, final_balance, overdrafts, tier, won

and the end-of-run statement is nothing more than an aggregate query over that history,

$$ \pi_{\,\mathrm{count}(*),\ \max(\mathrm{final\_balance}),\ \mathrm{sum}(\mathrm{overdrafts})} \bigl(\sigma_{\,\mathrm{account\_id} = a}(\textsf{ledger\_entries})\bigr) $$

while the account’s tier is a small linear search over a threshold table loaded highest-first, so the first balance ≥ threshold found by COBOL's SEARCH is already the best tier earned.

§6The CALL boundary

Lemma. Every scalar crossing a CALL ... USING BY REFERENCE boundary into C must occupy exactly as many bytes as the C parameter that reads it.

GnuCOBOL is free to store a one-digit PIC 9(1) COMP-5 in a single byte — and does. A C function declared to take an int* nonetheless reads and writes four. The difference is not truncation; it is three bytes of whatever COBOL field happens to follow in storage, silently overwritten on every call. This is the shape every field in gamesta.cpy and dbstate.cpy now avoids by declaring nothing narrower than a fullword, and it is why LEVELRC.cpy's file-derived fields use SIGN LEADING SEPARATE rather than a packed picture: a flat file is a boundary too.

§7Build

The toolchain is a Nix shell; nothing about it is installed globally. 

nix-shell            # cobc, gcc, pkg-config, SDL2, SDL2_image, sqlite
./build.sh            # compiles csrc/*.c, links against JUMPRUN.cob
./jumprun              # arrows/WASD to move, Up/W/Space to jump, Esc to quit
